## M1 已实现的行为

- 主窗口与 HUD 查询完整历史；正文按实际内容匹配，后台每 64 条让出主进程，并取消同窗口同入口的过期查询。HUD 保留预览与片段的模糊/拼音匹配，以及最近凭据的原有拼音取用能力。
- 复制捕获与取用次数分开：保留首次记录、最近复制、观察到的复制次数及来源记录。重复事件刷新列表和总数，不再制造虚假的新增记录数。
- “长期保存”创建独立数据库记录，图片创建独立文件。临时历史清理不删除置顶、长期保存或片段，也不再暗中删除超过 200 条的置顶内容。
- 保留策略支持条数、历史天数、图片天数和内容容量。天数/容量为 0 时不限该项；旧默认条数和图片 30 天规则保留。策略在下次捕获时生效，不因打开设置立即清库。
- 新图片保存捕获到的原始字节，列表单独生成缩略图；三种图片取用方式与独立路径复制统一处理。图片大小限制按实际保存字节判断。
- 主窗口与 HUD 共用主进程复制；片段 `{clip}` 使用当前系统剪贴板。失败不提示成功，也不关闭 HUD；错误、加载、空结果和键盘重试有测试。
- 暂停期间的过期采集与自身写入竞态得到保护；图片指纹覆盖全部像素，避免只改变中部时漏记。
- 新增偏好保存失败会明确报错，并使用临时文件替换，避免直接截断原偏好文件。

## 数据迁移与保护

新增 migration 024，按现有迁移链执行。旧内容和凭据不重写，不重新编号。旧版已覆盖的首次时间无法恢复，迁移记录显示“首次未知”，复制次数从迁移时已有的一条记录开始。

首次打开旧库时，迁移前使用 SQLite `VACUUM INTO` 保存含已提交 WAL 数据的一致性快照。文件位于数据库目录的 `migration-backups/`；有图片路径时，旁边的 `<备份名>.db.attachments/` 保存独立附件及原路径映射。旧库已经缺失的图片在清单标为 missing；其他附件复制或数据库备份失败会阻止迁移。未来版本数据库会被拒绝打开。

已验证 v23 → v24、再次迁移无变化、凭据表原样保留、WAL 备份可打开、附件副本完整、备份失败时旧 schema 不变、未来 schema 被拒绝。此验证使用合成数据库，不代表已经为用户日常数据库执行备份。

回退时应关闭应用，使用升级前数据库及配套附件恢复到匹配版本，再启动旧版。不要直接让旧版应用操作新增长期保存记录的 v24 库；旧版没有保护这些记录的规则。

## M0 实际验证结论

基线与复现方法见 `integrations/harness/README.md`。真实 SDK/runtime 在独立临时工作目录中完成 initialize、任务回执、`session.event` / `session.status`、本机模拟模型输出。两次实际模型请求中工具列表均为空；第二次保持模型流打开时关闭整个运行时，退出确认耗时 41 ms。

当前 SDK/runtime 均为 `0.1.3-alpha.1`，握手协议标识为 `0.0.1`，两者含义不同。审批回复、SDK 持久恢复和单任务取消不受支持；相关缺口不能用模拟批准或重建新会话绕过。M0 接入样例完成，**执行开放关口未通过**。

已增加身份/能力校验模块和测试。尚未实现真实凭据代理，也未证明任意命令的读权限、网络或子进程隔离。运行样例还依赖 OnSet 的已构建包，不是独立安装包。桌面中没有开放 AI 执行入口。

## 仍保留的边界

1. 剪贴板使用轮询：连续复制完全相同、未发生可观察变化的系统内容无法逐次计数；Windows 来源来自短时缓存，属于尽力识别。新的复制事件表示捕获到的变化，不是操作系统所有 Ctrl+C。
2. 旧版本丢失的原图、首次时间不能补造。新图片仍采用现有本地文件存储，尚未实现加密附件或临时明文租约。
3. 文件类型的长期保存仅保留路径引用，不备份外部文件内容。
4. 当前保留容量按记录内容字节计算，不是数据库及索引实际磁盘占用。长期副本、置顶和片段不计入临时历史上限。
5. 现有通用 JSON/CSV 导入和自动备份仍有历史局限：非片段历史不由导入器恢复，常规数据库备份不携带图片。本次新增的迁移备份单独保存附件；完整导出/恢复属于后续数据可靠性工作，不能把常规导出当作长期资料的完整备份。
6. 本轮未启动浏览器或应用 GUI；键盘、加载、空数据、错误和异步竞态由 jsdom 测试覆盖，布局采用现有 token 与可换行布局。真实窗口尺寸、系统剪贴板、全局快捷键及打包安装后的交互还需桌面验收。
