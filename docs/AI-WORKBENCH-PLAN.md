# ClipVault AI 编程工作台产品与开发方案

> 当前实施口径（2026-10-26）：底座直接采用 DeepSeek 官方 Harness 原项目，OnSet 只作产品案例参考；用户明确取消 Docker，改为经批准的本机 Node/npm 检查。本文是完整产品设计，含后续能力，不代表每一项都已上线；实际交付、验证与未完成范围以 [WORKBENCH-DAILY-VALIDATION.md](WORKBENCH-DAILY-VALIDATION.md) 为准。3.4.0 已支持两个独立目录任务并行，下方“首版”描述保留作设计历史。

方案日期：2026 年 10 月 25 日；实施修订：2026 年 10 月 26 日。核心首版已经实现，后续设计仍保留在本文。适用对象：产品负责人及后续开发 Agent。

ClipVault 升级为面向个人 AI 编程的主工作台：持续记录日常复制，管理项目所需的账号与密钥，把选中的资料交给 AI 执行任务，并保存可核验、可继续使用的结果。保留现有 Electron 桌面入口与本地数据能力，从官方 DeepSeek Harness 构建独立运行时，增加适合编程工作的项目、资料、任务和凭据工具。

首个完整版本的验收场景是：用户给出一段账号或 API 配置，说明所属项目与用途；工作台整理并保存资源；用户把剪贴板中的报错加入任务，让 AI 使用指定资源检查并修复测试项目；任务留下修改、检查结果和资源关联；重启后仍可找到账号、复制字段并继续任务。

## 1 产品范围与默认选择

| 项目 | 本轮确定的方向 |
|---|---|
| 主要用户 | 同时使用多个 AI 编程工具、频繁切换项目、账号、接口与代码资料的个人开发者 |
| 产品入口 | Windows 桌面主工作台、托盘后台、全局快捷搜索窗口；沿用 ClipVault 的组件和设计语言 |
| 数据策略 | 剪贴板、资源与任务关系在本机管理；调用远程模型时，只发送本次选择并处理过的上下文 |
| AI 执行 | 使用官方 DeepSeek Harness 独立运行时；模型提供方通过适配器配置，产品概念不绑定单一模型名称 |
| 默认工作方式 | 用户给任务后自主完成已授权的本地工作；资源不明确、目标变化或超出授权范围时集中提问 |
| 首版并发 | 一个活动编程任务，其他任务可排队；每个活动任务拥有独立运行时进程与 Session 归属 |
| 与已有工具协作 | 首版可复制或导出脱敏任务上下文、补丁说明和结果；Codex、Claude 等外部工具的深度接入另做适配 |
| 数据迁移 | 保护现有凭据、历史、片段和设置，采用增量迁移；旧库保持可备份、可核对 |

第一版暂缓跨设备同步、团队、浏览器扩展、任意网站自动登录、多 Agent 并发和自动生产发布。账号的“打开登录页＋复制字段”先完成；自动填表需后续浏览器接入、域名匹配与人工接管机制。历史 Vera、P2P、CLI/HTTP/SSH 模块不作为本轮实现基础。

## 2 主工作台的产品形态

主导航保留四个入口，设置作为辅助入口。

| 入口 | 用户来这里做什么 | 主要内容与操作 |
|---|---|---|
| 工作台 | 发起工作、查看执行、处理需要自己决定的事项 | 当前任务、输入区、所用资料、工具动作、修改与验证、继续任务 |
| 项目 | 恢复一个项目的工作环境 | 仓库与工作目录、用途、环境、常用资源、最近任务、可确认的项目事实 |
| 剪贴板 | 找回复制过的内容并立即使用 | 时间线、全文搜索、来源与类型筛选、预览、复制、选择后加入任务或保存资源 |
| 资源 | 取用长期保存的账号与工作资料 | 账号、API 服务、数据库连接、代码片段、常用命令、网址、说明；按项目和环境查找 |

全局快捷窗口覆盖四类对象的搜索。空输入展示最近使用；输入关键词后查询全库。结果明确显示对象类型、项目、环境和可执行动作，防止把生产凭据误当成测试凭据。复制本身不调用模型；AI 操作需要用户选择对应动作。

工作台输入区支持普通任务输入和“保存账号或密钥”入口。用户直接粘贴混合内容时，在本地先识别敏感字段，形成可修改的资源卡；发送给模型的任务描述只带引用与必要元数据。用户无需预先填写一整套复杂表单。

首页展示真实待办和当前工作，不增加需要维护的统计面板。没有任务时提供“粘贴资料开始”“打开项目”“找回剪贴板”三个入口；有任务时突出当前进度、阻塞原因和下一步。

## 3 三条主要工作流程

### 3.1 复制内容后找回并用于工作

1. 应用在后台运行时，按用户设置采集文字、HTML、图片和文件路径，遵守暂停记录与排除应用规则。
2. 相同内容合并展示，单独记录复制发生的时间与可靠来源。首次复制、最近复制与取用次数分开，不以更新时间冒充首次时间。
3. 用户在快捷窗口快速复制，或在剪贴板页按时间、来源、类型和项目查找。无法可靠判断项目的内容保持“待归属”。
4. 用户选中报错、接口地址和配置，加入当前任务；工作台展示将发送的资料范围，并为敏感字段替换引用。
5. 被任务采用或被用户长期保存的资料建立独立快照。临时历史到期后，任务资料和资源仍有效。

“置顶”只控制展示顺序，“长期保存”决定保留方式。容量到达限制时展示占用和可清理范围，不静默清理长期资源。文件路径记录不等于文件备份；加入任务时明确选择引用现有文件或复制为附件。

复制为附件后保存固定字节与内容哈希；引用外部文件则记录路径、哈希和可用的仓库修订信息。每次读取、发送或恢复时重新核对外部引用；文件变化或丢失时要求重新选择或生成新版 ContextBundle，不能把路径下的新内容冒充旧快照。只有已复制的附件保证不受外部文件删除影响。

图片继续提供仅图片、仅路径、图片与路径三种取用方式。新图片应保留原始字节并另生成缩略图；旧版已缩小的图片无法恢复原始分辨率。加密附件通过应用预览，向外部程序提供路径时临时导出，展示有效期；主动导出到用户指定目录的文件由用户管理。

### 3.2 一段账号资料变成可重复使用的资源

示例输入：“这是资料助手测试后台，账号和密码在这里，接口地址也一起记住，之后帮我检查登录。”

1. 本地输入处理识别账号、密码、地址、API Key 等字段。确认不了的字段保留为待整理项，不推测密码含义、不自动覆盖旧账号。
2. 建立资源卡：名称、项目、环境、用途、登录地址或 API 端点，以及分别保护的敏感字段。一个服务可以有多个账号或多个密钥版本。
3. 发现相同服务或用户名时提示“新增账号／更新已有资源”；更新凭据保留版本与变更时间，不因地址相似就合并。
4. 下次搜索项目名、用途、别名或环境即可找到。复制账号、密码、Key、连接地址分别是独立动作；敏感字段不随列表批量返回渲染进程。
5. 资源的状态区分“已保存”“待验证”“指定范围验证成功”“已过期或被撤销”。保存成功不能表示登录成功。

“检查登录”第一版优先支持有明确接口的认证检查和打开登录页后的手动取用。网页 MFA、验证码、风控和人工确认显示为需要用户接管；不把 API 探测成功说成网页已经登录。

从历史提升的敏感内容继续标记为敏感，普通搜索结果遮挡原文。原始历史如继续保留，仍在本机加密保存且不进入普通任务上下文；是否清理原文由用户的保留设置决定。

### 3.3 AI 编程任务使用资源并留下结果

示例任务：“用资料助手的测试 API 检查这段 401 报错，修复当前项目的连接配置，跑相关测试。”

1. 任务绑定一个明确工作目录、项目和环境，带入选中的报错资料以及凭据引用。发现多个候选账号时让用户选择。
2. 执行前核对仓库状态和任务范围。复用现有修改；需要隔离时使用独立工作目录或 worktree，并记录来源提交。
3. Harness 负责推理、计划和工具调用；项目工具读取资料、申请资源使用、检查接口、修改文件、运行验证。
4. 需要密码或 Key 的动作交给本地凭据代理。模型只获得资源引用、动作结果与脱敏诊断。
5. 结果卡列出修改文件、差异、实际运行的检查、退出码与未解决事项，并关联本次使用的资源版本和目标环境。
6. 用户重启后可以恢复任务记录，再次运行时重新检查仓库、资源版本和执行状态。资源可显示“上次用于任务 X，在测试端点验证成功”，但不会把一次成功推广到所有场景。

任务成功必须来自验收项和实际工具证据。模型回复“已经完成”、进程进入 idle 或 HTTP 返回 200，都不能单独作为成功依据。HTTP 成功还需核对预期响应、身份或接口能力。

## 4 数据对象及其关系

以下为拟新增或扩展的数据对象，名称是设计名称，尚非现有接口。

| 对象 | 关键内容 | 保存与关联规则 |
|---|---|---|
| Project | 项目名称、说明、默认环境 | 一个项目可有多个工作目录、任务和资源；项目默认值不覆盖任务明确选择 |
| Workspace | 规范化路径、仓库、分支或 worktree、来源提交 | 任务绑定具体工作目录；路径更名需重新定位，不悄悄切到另一个目录 |
| ClipItem | 类型、加密内容、摘要、内容指纹、敏感级别 | 表示一份内容；内容指纹不能单独证明来源或授权 |
| ClipOccurrence | ClipItem 引用、发生时间、来源应用、可确认的项目 | 保留重复复制的轨迹；对旧数据标记“迁移记录”，不伪造已丢失的首次时间 |
| Resource | 名称、类型、用途、项目、环境、网址、状态 | 长期资产；支持账号、API、连接配置、片段和资料等类型 |
| SecretField | 所属资源、字段名、密文、版本、撤销状态 | 密码、Key、私钥、令牌分别保存；普通资源列表仅含遮罩与配置状态 |
| ContextBundle | 用户选中资料的快照或带哈希的外部引用、来源、版本、脱敏结果 | 与一次任务或一次追加输入关联；创建后固定；外部引用变化必须重新确认并生成新版本 |
| Task 与 TaskRun | 目标、验收项、工作目录、输入、运行时版本、Session ID、状态 | 一个任务可有多次尝试；每次尝试有独立 Run，保留之前的结果 |
| ActionReceipt | 工具动作、目标、授权、状态、外部请求 ID、幂等键 | 发起前登记意图，完成后登记结果；未知结果先核对，避免重复执行 |
| Artifact 与 Verification | 补丁、文件、检查结果、哈希或修订号、时间 | 引用真实产物；原文件变化后将对应验证标记为过期 |

用户数据由 ClipVault 的本地服务管理。Harness 负责自己的 Session 日志，业务数据库保存 Session 与 TaskRun 的映射和可重建的结果索引。两边不共享直接写同一数据库的权限，也不把 Session 日志当成资源库。

项目事实与模型推断分别记录。只有用户明确保存或经工具验证的内容才能成为持久项目事实，并保留来源；模型总结作为可编辑摘要，不能改写凭据或覆盖项目配置。

## 5 采用官方 DeepSeek Harness 的具体方式

用户已明确 OnSet 仅作成功案例参考；本产品不以 OnSet 的源码、SDK、运行时或数据为依赖。正式来源是 DeepSeek 官方仓库和官方 npm 包。

### 5.1 已固定的基线

- 官方仓库：https://github.com/deepseek-ai/deepseek-harness
- 提交：`687f282e8625c6b8d11ff58211a90524be2e4317`，标签 `dsh-v0.2.1-rc.2`。
- SDK 与 runtime 同为 `0.2.1-rc.2`；独立 Node `22.22.1`。
- 用户已确认将本项目 Zod 覆盖到 `4.6.6`，修复已公布的内存耗尽问题。
- 来源契约在 `integrations/harness/official.lock.json`；依赖完整性在根 `package-lock.json`；构建后的每个运行文件哈希与许可证在运行时 manifest 中。

### 5.2 进程与能力

Electron 主进程管理剪贴板、加密库、项目、任务、审批和真实密钥。每个活动任务启动独立 Node worker，经官方 SDK 启动官方 Harness 内核。仅挂载工作台自己的六个受控工具，不挂载上游通用终端、editor、外部日志或遥测插件。

当前固定 SDK 支持 `resumeSession`；本地审批由主进程代理实现，绑定任务、运行、目标、具体输入指纹和有效期，不宣称 rc.2 已具备较新上游版本的原生审批接口。停止会取消本地请求、等待工具结束并关闭任务运行时。未确认的结果保留为中断。

模型认证只在主进程固定 HTTPS 目标处注入。项目 API 验证只允许保存地址上的 GET/Bearer 请求，并拒绝重定向。按用户最新决定，本机执行 `node --test` 或白名单 npm 项目检查脚本；在文本副本中运行、复用已有依赖，不注入密钥、不自动安装依赖。每次命令审批明确当前账户权限和网络访问能力，不把它称为容器或系统隔离。

### 5.3 独立构建与数据

| 路径 | 职责 |
|---|---|
| `integrations/harness/runtime.mjs` | 官方插件组合与持久化内核 |
| `integrations/harness/worker.mjs` | 官方 SDK 启动、恢复、通知和停止 |
| `integrations/harness/tools.mjs` | 六个工具调用本机授权代理 |
| `scripts/build-harness.mjs` | 独立 Node、JS 内核、原生依赖、许可证与哈希清单 |
| `src/main/workbench/` | 任务服务、审批、代理、文件、本机检查、加密会话归档 |
| `src/db/workbench-store.ts` | 项目、资源版本、任务、回执与加密持久化 |
| `src/preload/workbench-api.ts` | 桌面类型化接口 |
| `src/renderer/src/pages/` | 工作台、项目与资源库；旧功能继续可达 |

构建使用 `npm run build`，验证使用 `npm run verify:harness` 和 `npm run test:native`。运行时通过 electron-builder 的 `extraResources` 放置，不从其他项目读取代码。会话运行期间使用任务专属目录，退出后封入 DEK 加密数据库；异常退出时保留原目录供下次归档。备份包含已归档会话；旧图片文件仍属于原有图片存储体系。

此前 OnSet M0 报告仅为历史记录，不能作为正式官方 Harness 验收依据。历史脚本已停用。

## 6 凭据和上下文如何打通

### 6.1 本地导入与模型输入

原始粘贴内容在进入聊天记录、模型请求、任务摘要和诊断日志之前先经过本地处理。已识别密码和 Key 转入 SecretField，替换为资源引用；可疑但未能可靠解析的输入留在本地整理区，由用户指认字段。首版不把混合凭据原文直接交给远程模型分类。

敏感识别不能保证覆盖任意格式，因此“保存账号或密钥”入口默认将整个输入视为敏感。普通任务输入的本地检测与发送范围预览作为补充；资源敏感值不进入持久全文索引、向量索引、AI 自动摘要或模型工具返回值。

资源元数据也可能包含私有网址和业务信息，模型只获得当前任务需要且被选择的字段。原始剪贴板与历史上下文不会作为每次对话的默认背景发送。

### 6.2 凭据使用代理

凭据代理是本地应用中的受控执行组件：接收“使用资源 R 的字段 F，对目标 T 做操作 O”，核对范围后在执行时读取秘密，向调用者返回脱敏结果。它不提供模型可调用的通用 `get_secret` 接口。

授权至少绑定项目、环境、任务、资源及字段版本、目的地址、操作种类和有效期。用户明确授予的任务内授权可以复用，避免每次请求重复确认；目标、版本或操作范围变化时重新决定。用户撤销或任务停止后，后续使用立即拒绝。

| 用途 | 执行方式 | 模型能得到什么 |
|---|---|---|
| 用户手动复制密码或 Key | 主进程读取指定字段并写入系统剪贴板；应用自己的写入不会再次成为普通历史 | 复制结果，不含值 |
| 检查 API 连接 | 代理向已绑定端点注入认证信息并执行已定义的检查 | 状态、耗时、身份或能力验证结果、脱敏错误 |
| 调用工作台自身模型 | 专用提供方适配器经代理发送模型请求；主模型 Key 与项目凭据分开管理 | 正常模型响应，不含认证头 |
| 项目运行时需要环境变量 | 首版暂不开放秘密注入；后续仅向具备执行限制且被明确授权的子进程注入指定字段 | 退出码与脱敏输出；必须说明该项目进程能够读取被注入的值 |
| 项目确实需要本地配置文件 | 首版生成字段占位或资源引用；秘密落盘作为后续独立能力，需目标文件、版本控制状态及留存方式的明确授权 | 首版返回文件位置与字段引用；秘密落盘不能沿用“值只在代理内部”的承诺 |

端点检查规范化协议、主机、端口和允许路径，重定向不得自动把认证信息转发给新目的地。自托管和本机地址可显式登记；禁止任意工具把凭据代理当作可访问任何内网地址的通用转发器。响应、异常、命令、差异与附件发布前均经过输出过滤；检测到秘密则阻断原始输出并提示处理。

首版以专用连接检查工具优先；把秘密注入项目命令会让该项目代码获得秘密，也可能直接联网发送，输出脱敏不能阻止这一行为。通用终端不继承全部父进程环境，也不自动读取工作台的密钥文件。秘密注入与秘密配置落盘均留到 M5 单独设计与验收；M3、M4 的默认流程使用代理与占位配置。

### 6.3 Harness 插件与通信

工作台插件只暴露任务需要的资料查询、资料读取、资源描述、连接检查、产物登记等操作。本地服务再次核对 TaskRun 归属与授权，不能只相信插件传来的项目 ID。普通资料工具不能绕过敏感字段规则。

建议接口如下；这些是待实现的产品接口，不是对 Harness 现有 API 的声明。

| 接口 | 输入概念 | 返回概念 |
|---|---|---|
| `context.search` | 当前项目或已授权集合、关键词、类型、游标 | 有界结果和脱敏摘要 |
| `context.read` | 已授权资料 ID 与版本 | 固定版本内容、来源与敏感处理状态 |
| `resource.describe` | 资源 ID | 名称、环境、允许动作、字段是否配置、验证范围 |
| `connection.check` | 资源引用、已登记目标、检查类型 | 结构化验证结果及审计 ID |
| `artifact.register` | 当前任务产物路径、类型、验证引用 | 校验后的产物 ID；路径必须在允许范围内 |

UI—主进程继续使用受校验的 Electron IPC。Node worker 与主进程采用私有控制通道；运行时插件到主进程的桥接在 M0 选择并验证，Windows 优先本机命名管道，其他平台对应本地域套接字。必须绑定运行实例、校验对端和操作范围，不能把知道通道地址当作授权，也不开放通用局域网 HTTP 密钥接口。

M0 导出最终实际加载的插件和工具清单，并逐项确定以下处理方式，不能只在现有 base 上叠加新工具。

| 原有能力 | 首版处理 |
|---|---|
| 文件读取、搜索、替换工具 | 替换或强制路由到工作台文件服务，校验规范化路径、链接目标和任务目录；拒绝 vault、应用私有目录与未授权外部路径 |
| PowerShell、Bash、后台 jobs | 不装载通用 shell 插件；本机只支持明确批准的 Node/npm 检查命令，限制时长并尝试停止进程树；无法确认停止时阻止静默继续 |
| subagent、fork 与工作流执行器 | 首版关闭；以后启用时继承同一资料范围、执行限制和授权撤销机制 |
| 默认 credentials-local、环境及 `.env` 凭据回退 | 从该 profile 移除，使用工作台代理；不继承其他项目或用户目录中的密钥 |
| 运行期插件安装、自修改、动态加载配置 | 首版关闭；项目或 home 下的任意 Cordis 补丁不得自动加载，最终组合必须符合清单 |
| 网络与外部服务工具 | 带认证请求只交给固定目的地的凭据代理；经用户批准的本机项目脚本仍可自行访问网络，不作禁网承诺 |

任务启动时读取适用的项目规则，确定本次工作范围；读取到的项目说明、历史内容和外部网页不能自行扩大凭据授权或启用新插件。普通资料中的指令按资料处理。

### 6.4 明确的保护范围

沿用 ClipVault safeStorage 包装密钥与敏感值加密，但不把它描述成能隔离同用户恶意进程的保险箱。没有复用或修改 OnSet 的 ACL、运行时和数据。

文件工具与认证代理通过合成秘密、路径越界、链接、撤销和过期授权测试。实际加载插件仅包含受控工具。用户明确选择的本机执行器具有当前账户权限，可能读取本机其他文件或联网；清空环境和脱敏不能提供系统隔离。模型与资源密钥不注入检查进程，原始项目文件的哈希在执行后重新核对。

本机检查需用户确认信任项目及其 npm 脚本。默认 2 分钟上限，停止时处理受管进程树；未确认停止则保留副本与中断回执，下次启动须核对，不能冒称已结束。同用户恶意进程及脚本的系统级限制属于未提供的保护范围。

当前 ClipVault 图片文件未按凭据方式加密，新附件需定义独立的加密保存与临时导出流程。任务选中的普通代码和脱敏输入会进入 Harness Session 日志，首版应明确它们的本机保存位置与保留策略，不承诺全部任务文件均已加密。

专用 profile 不装载附加日志提交、OTel Session 遥测和通用本地凭据回退插件；保留本地 Session 持久化。这不阻止必要上下文作为模型请求发送给所选提供方。实际插件与工具清单见 `integrations/harness/official.lock.json` 及运行时验证报告。

## 7 任务生命周期与中断恢复

| 状态 | 进入条件 | 用户可做什么 |
|---|---|---|
| 草稿 | 任务尚未发起或范围未确定 | 编辑目标、资料、项目与资源 |
| 排队 | 已就绪但当前执行槽被占用 | 查看、撤回、调整顺序 |
| 执行中 | 运行时就绪且开始处理已接收输入 | 查看动作、追加资料、请求停止 |
| 等待用户 | 缺少业务信息、资源歧义或需要具体授权 | 回答、选择、批准或拒绝 |
| 验证中 | 已产生改动，正在检查验收项 | 查看检查过程与产物 |
| 已完成 | 必要验收项已有通过证据 | 复制结果、打开差异、发起后续任务 |
| 失败 | 有明确错误，当前尝试无法完成 | 查看原因、修正后新建尝试 |
| 已中断 | 崩溃、连接丢失，实际结果需要核对 | 先核对进程和外部动作，再恢复 |
| 已停止 | 用户请求停止，相关本地进程已确认退出 | 查看已产生的改动，再决定继续 |

“停止中”作为过渡状态持续展示，不能靠超时就假称已停止。终止本地进程不会自动撤销已发出的远程请求，也不会撤销已写入文件的内容。请求回执和差异始终保留。

任务业务状态由应用服务更新，依据 SDK 事件、工具回执和验证结果驱动；Session 日志负责会话重建。每条映射记录带 runtimeInstanceId、TaskRun ID、Session ID 和事件位置，防止重连后重复计数或串到其他项目。

有副作用的操作在执行前记录 ActionReceipt，并绑定输入指纹与授权。崩溃后若已有外部请求 ID，先查询状态；没有幂等能力且结果未知时停止自动重试，向用户展示待核对项。会话恢复不能恢复原终端、浏览器登录态或外部请求的执行现场。

同一工作目录首版只允许一个写任务。恢复时检查文件变化、Git 状态、凭据版本和旧进程；输入变化会让之前的计划授权或验证过期。不得为“恢复任务”重置用户新修改的文件。

任务可以配置模型请求次数、运行时长与可获得的用量上限。达到上限时停止发起新动作并保留结果，等待用户继续；未知价格或未知用量显示为未知，不按零计算。模型持续失败时限制重试次数，避免无限循环。

## 8 开发顺序与验收关口

按 M0 → M1 → M2 → M3 → M4 → M5 推进。M0 中完成对象与接口约定后，M1 的本地剪贴板开发可与运行时验证并行；M3 必须等待运行时关口和资源模型通过。每阶段交付可用行为及相应证据，不能只以页面完成度验收。

### M0 锁定工程边界并验证 Harness 接入

**交付：** 固定运行时来源与补丁清单、对象与接口约定、独立 Node 执行样例、审批与恢复兼容性结论、Windows 进程退出和权限约束证据。

**顺序：** 工程基础审计 → 固定源码及 profile → 用无密钥模拟提供方贯通启动、事件和停止 → 验证审批、拒绝、取消和过期回答 → 验证持久恢复 → 验证本地服务桥接与凭据代理 → 确定运行时包。

**验收：** SDK/runtime/profile 不匹配时明确拒绝；审批不可用不会放行动作；停止后受管进程退出；恢复不伪造新 Session；配置关闭附加日志外发；模型与项目密钥不会出现在普通环境、日志或回执；在不依赖 OnSet 开发目录的测试位置启动。

**范围：** 拟建 `src/main/harness/`、`integrations/harness/`、共享类型与专用测试夹具。此阶段不接真实用户资源，不对用户工作仓库执行写操作。

**阻断项：** 若审批、恢复、代理隔离或进程退出无法证明，保留本地能力与只读演示，停止进入可写 AI 任务；不得临时用自动放行来绕过。

此处“代理隔离”指实例与任务身份校验、目的地址约束、撤销和过期请求拒绝；本机执行的信任边界按 6.4 及用户最新决定执行，不再以 Docker 为交付前置条件。

### M1 做好日常剪贴板和统一取用

**交付：** 全库搜索、复制事件模型、原图与缩略图、清晰保留策略、长期资料快照、主窗口与 HUD 统一复制服务。

**验收：** 第 40 条以外的记录可查；同一内容重复复制仍保留首次和来源；重要资料不受临时历史清理影响；暂停和排除应用生效；复制失败明确反馈；自身复制不产生循环；片段 `{clip}` 在所有入口行为一致；图片三种取用方式保持可用。

**范围：** `src/main/clipboard/monitor.ts`、`src/main/ipc/clipboard-handlers.ts`、`src/main/storage/image-store.ts`、`src/db/clipboard-store.ts`、`src/db/migrations/`、`src/types/clipboard.ts`、`src/renderer/src/pages/ClipboardPage.tsx`、`src/renderer/src/hud/commands/mixed-data.ts`。

搜索先实现统一查询与后台分批检索，再根据基准选择内存索引。内容保持加密落盘，敏感字段不进入普通全文索引；不能为了搜索直接建立一份明文秘密索引。搜索未加载完时显示“仍在检索”，避免把部分结果说成全库无结果。

### M2 建立项目与可复用的账号资源

**交付：** Project、Workspace、Resource、SecretField；现有凭据与片段的兼容迁移；混合内容本地整理；字段复制；项目和环境过滤；资源版本、撤销、备份与恢复。

**验收：** 一段账号资料可保存、搜索、按字段复制、修改与撤销；同服务多个账号不混淆；测试与生产环境清楚区分；旧凭据和 TOTP 等已有关联仍可用；重启后可取用；历史清理后资源独立存在；模型尚未启用时这些流程也能完成。

**范围：** `src/types/credential.ts`、`src/db/credential-store.ts`、凭据审计与迁移、`src/main/ipc/credential-handlers.ts`、资源与项目页面、新增本地导入和凭据代理模块。

M2 完成后可以先作为日常本地工作助手使用，不等待 AI 完整执行能力。

真实凭据在迁移、字段取用和加密备份恢复通过后，可用于 AI 执行关闭状态下的本地保存与手动复制。此门槛不等于授权 Harness 使用这些凭据。

### M3 打通第一个真实编程任务

**交付：** 工作台任务输入、资料选择、任务内资源授权、受控文件与命令工具、API 检查、差异与验证结果。

**唯一主验收场景：** 在专用测试项目中，选择一条 401 报错与一个测试 API 资源；AI 检查连接、修正代码或配置、运行相关验证；结果显示修改与证据，资源记录本次使用范围。先用模拟服务和合成凭据，随后在明确选择的真实测试服务上验证。

**验收：** 密钥未进入提示词、工具参数、Session、stdout、diff、诊断与导出；错误账号或错误环境不会被自动替换使用；拒绝授权、端点变化、工具失败和模型失败均能正确停止或等待；网络或模型不可用时本地剪贴板继续工作。

连接真实测试服务前，必须通过 M0 和集成后的合成凭据测试，包含拒绝、撤销、停止、连接丢失、越界读取、直接外发与输出泄露；先使用权限有限的测试资源，并明确选定目标。基本停止和撤销能力属于 M3 前置条件；M4 完善恢复体验和异常覆盖，不把这些基础条件推迟到 M4。合成秘密扫描证明的是所测通路，不作为任意代码、任意编码都绝不泄露的保证。

**范围：** `src/main/workbench/`、工作台工具插件、上下文处理、凭据代理、任务数据库与事件映射、工作台 UI。只依赖一个模型提供方完成首条流程，暂不同时铺开多个适配器。

### M4 达到每天可以依赖的状态

**交付：** 任务恢复、外部动作核对、可靠停止、保存后继续、资源版本关联、有效备份、运行时升级与回退、清晰的离线和错误状态。

**验收：** 在发起前、已发起未收回执、修改文件后、验证中四个位置模拟中断，均能正确识别事实；不会重复提交副作用动作；已有修改不丢；旧数据迁移与备份恢复可核对；升级不覆盖用户目录；Runtime 故障不影响历史检索。

M3 是功能打通，M4 通过后才将它作为主工作台交付。

### M5 扩展取用和自动化能力

依据实际使用频率增加本地 OCR、明确范围的语义检索、任务模板、外部 AI 工具适配、浏览器填表和多个任务并行。浏览器填表需保留域名核对、MFA 接管与退出机制；并发需先解决同目录写冲突、进程取消和凭据授权隔离。

开发顺序由“用户找不到什么、重复填写什么、哪类任务经常中断”决定。跨设备和团队能力另立方向，不附带进入这一轮。

## 9 数据迁移与版本回退

当前数据库入口是 `connection.ts`，实际版本迁移由 `src/db/migrations/` 执行。新增结构应加入该执行器，避免在 `initSchema` 旁另建迁移系统。[数据库入口](E:/粘贴板/粘贴板/ClipVault/src/db/connection.ts:93)

迁移按新增表／字段、可重试回填、校验、切换读取顺序进行。旧凭据 ID 保持稳定或建立明确映射，保留审计、TOTP、快捷键与分类关联。旧数据中已经丢失的首次复制时间和原始图片不能补造。

迁移前建立一致性备份，覆盖数据库、必要附件与恢复信息；WAL 模式下不能只拷贝正在写入的数据库主文件。回填按检查点推进，失败时显示范围和原因，不把解密失败当作空值成功迁移。

备份格式纳入新增资源、敏感字段、资料快照、任务关联，以及恢复会话所需的 Harness Session 日志、持久附件、事件检查点和运行时/profile 清单。备份先让相关写入到达一致检查点，再打包业务库与 Session；恢复前检查数据格式与运行时兼容性。运行时二进制可单独安装或从校验过的安装包恢复，清单必须能定位匹配版本。

跨设备备份继续使用独立密码保护；只带 safeStorage 包装数据无法保证换一台机器恢复。外部代码仓库和“仅引用”的文件不默认包含在应用备份内，恢复时由用户重新定位并核对哈希。缺少 Session 或匹配运行时时，旧任务只能查看已有结果，明确显示不能原会话续跑，不伪造恢复成功。

回退分为两种：关闭新工作台功能仍使用当前兼容数据，或恢复迁移前备份。旧应用若不支持新 schema 则拒绝直接打开，不宣称任意版本可以无损降级。恢复旧备份前先导出迁移后的新增数据，明确时间差和影响。

M0 需要用原型回答四个问题：官方审批与恢复能否小范围回移；Windows 上哪些执行限制能实际落实；本地服务桥接能否拒绝伪造或过期调用；随包 Node 与运行时能否在独立安装位置完整退出和恢复。这些影响实现路径，不改变已经确定的产品方向。M0 完成后再给 M3、M4 的工期估算，避免用未经验证的 SDK 能力排期。
