# 团队协作

ClipVault v2.0 支持**去中心化 P2P 团队协作**：无需服务器，局域网即可与同事安全共享指定凭证和剪贴板。

## 架构概览

```
设备 A ─┬── mDNS 广播 (_clipvault._tcp) ──┬─ 设备 B
        │                                  │
        ├── Noise IK 握手（首次配对）─────┤
        │                                  │
        └── WebRTC DataChannel ────────────┘
                     │
             Yjs CRDT 同步（共享集合）
                     │
         XChaCha20-Poly1305 消息层加密
```

- **mDNS**：自动发现同一局域网的 ClipVault 设备（macOS 需在权限授权时允许本地网络）
- **Noise IK**：首次配对时的认证握手，防中间人（需双方确认 QR + 数字码）
- **WebRTC**：跨网段（如 Tailscale / ZeroTier）穿透能力
- **Yjs CRDT**：保证多端离线编辑后重连的最终一致性

## 设备配对

### 扫码法（推荐）

1. 设备 A 打开「团队 → 添加设备」，显示二维码 + 6 位数字确认码。
2. 设备 B 打开「团队 → 扫描」，对准 A 的二维码。
3. 双方界面显示相同的 6 位数字，点击「确认」完成配对。

![配对 QR + 数字](placeholder.png)

### 手动法

如果 mDNS 失效（公司防火墙禁止多播），可手动输入对方 IP + 连接码。

## 共享范围

配对成功后，**不会**自动同步所有数据。必须显式将条目加入**共享集合**：

| 共享集合 | 内容 | 典型场景 |
|----------|------|----------|
| 团队凭证 | 指定的凭证 | 团队共用 API Key、堡垒机账号 |
| 团队剪贴板 | 一次性文本/链接 | 会议上快速分享 |
| 团队片段 | 常用代码 / 话术 | 客服团队知识库 |

每个共享集合有独立的**成员列表**和**权限矩阵**（可读 / 可写 / 可删）。

## 冲突解决

- **并发编辑**：Yjs CRDT 自动合并，文本字段按字符级合并，非文本字段走 LWW（last-writer-wins）
- **网络分区**：重连后增量同步，缺失操作自动补齐
- **成员离线**：操作缓存在本地日志，上线后回放

**删除语义**：采用 tombstone 标记，默认保留 30 天供恢复；彻底清除需团队所有成员都同步完毕。

## 故障排查

### 发现不到对方设备

1. 确认两端连接同一 WiFi（或 VPN 段）
2. 检查防火墙：允许 `clipvault` 入站 UDP 5353（mDNS）和 TCP 动态端口
3. macOS：系统设置 → 隐私 → 本地网络，勾选 ClipVault

### 配对后无法同步

- 点击「团队 → 诊断」查看连接状态（ICE / DTLS / 数据通道）
- 查看审计日志中的 `sync_error`
- 重启应用重建 WebRTC 连接

### 加密保证

即使局域网中有恶意监听者，也无法解密流量：

- 握手阶段：Noise IK 模式提供前向保密 + 身份认证
- 业务阶段：XChaCha20-Poly1305 AEAD + 每会话 nonce 计数器
