# ClipVault × Harness 原生重设计（草案 v0.3）

日期：2026-10-26。状态：**路线已定（B），P0 范围待确认**。本文档不改动现有代码与数据。

## 1. 为什么要重做

现状（3.4.0）是"旧剪贴板应用 + 一个任务页"：

- 导航按数据类型分模块（剪贴板 / 凭证 / 片段 / TOTP / 健康 / 概览 / 设置），工作台只是排在第一位的页面。
- 工作台是表单：目标 + 验收 + 手选剪贴板/附件/资源 → 运行。挑上下文、判断要哪个密钥、写验收，都由人来做。
- Harness 只在点"运行"那一刻启动一个 worker，跑完即退出。会话、计划、审批、追问这些 Harness 自带能力，全被自建的简化版替代了。
- 剪贴板捕获、搜索、资料整理全程不经过 Agent，三类资料没有被串起来。

## 2. 决策记录

- **2026-10-26 主人选定路线 B：自建界面，只用官方 Host。**
- 含义：
  - 界面完全自己设计，继续用现有 React 18 + Tailwind + Radix 技术栈。
  - Agent 侧不再"只当执行器"，改为常驻的会话运行时：会话、目标、计划、待办、审批、追问、子 Agent 都用官方 Host 的实现。
  - 不采用官方 Web 前端（`dsh-web-frontend` / `dsh-client-ui-*`）。
- **2026-10-26 主人要求：剪贴板是一级功能，现有能力一项不能少。** 必须做到三点：随时复制随时存、能方便地找出来粘贴、AI 能帮忙管理好。详见第 6.3 节。
- **2026-10-26 主人要求：账号密钥智能管理。** 用户给一段账号、密码、密钥，说明用途后，系统整理成结构化资源，方便下次搜到、依次粘贴、辅助登录；秘密值不发给模型。详细规格见 [DEV-SPEC-HARNESS-NATIVE.md](DEV-SPEC-HARNESS-NATIVE.md) 第 6 节。
- 完整开发文档：[DEV-SPEC-HARNESS-NATIVE.md](DEV-SPEC-HARNESS-NATIVE.md)。实现以开发文档为准。
- 默认取值（主人未表态前按此执行，可随时改）：
  - TOTP、片段、原有凭证、健康报告收进"更多"；剪贴板和资源保持一级入口。
  - AI 自动预分析（第 8 节的 L2）按项目默认关闭。

## 3. 新定位与原则

> 以 Harness 会话为中心的个人编程工作台。剪贴板是 Agent 的短期记忆，资源库是 Agent 的受控能力，项目是 Agent 的工作区。

1. **会话是一等对象。** 一切从"开个会话说一句话"开始；任务、计划、验收都是会话里的状态，不再有独立的"任务表单"。
2. **资料即上下文。** 剪贴板、资源、项目以 mention 和工具的形式暴露给 Agent。Agent 自己去找，人只需确认。
3. **对话 + 主动并存。** 用户可以随时开口；系统也会根据复制行为主动给建议，但默认不把剪贴板发给模型。
4. **秘密不出主进程。** 模型只拿到资源 ID 和字段名；凡是用到秘密的动作，都由 Electron 主进程代为执行。
5. **界面自建，概念用官方。** 会话、轮次、目标、计划、待办、审批、追问、子 Agent 这些名词和状态机都沿用 Harness 的定义，界面只负责把它们画好，不另造一套平行概念。

## 4. 架构

```text
┌──────────────── Electron 主进程（可信，持有密钥）────────────────┐
│ vault 解锁 / safeStorage / SQLite 加密库                         │
│ 剪贴板监听、本地识别（收件箱）、全局快捷键、托盘、OCR、登录窗口  │
│ HostManager：按会话起停 Host、事件投影、审批/追问队列            │
│ capability bridge：按会话签发令牌（模型代理、工具、存储、控制）  │
└───────▲───────────────────────────────┬───────────────────────────┘
        │ IPC（固定方法）                │ stdio JSON-RPC + 本机 HTTP 能力通道
┌───────┴──────────────┐      ┌──────────▼─────────────────────────────┐
│ Renderer（自建 React）│      │ Harness Host 进程（每个活跃会话一个）    │
│ 对话 / 收件箱 / 资料库 │      │ 官方插件：session、agent-loop、goal、    │
│ 会话事件投影 → UI      │      │ plan-mode、todo、user-approval、          │
└──────────────────────┘      │ user-questions、subagent、compaction…   │
                              │ 自建插件：vault-persistence、            │
                              │ clipvault-tools、clipvault-control       │
                              └──────────────────────────────────────────┘
```

### 4.1 为什么是"每个活跃会话一个 Host 进程"

官方 SDK 协议（`dsh-sdk-protocol`）只有 `initialize`、`session/prompt`、`session/resume`、`session/wait`、`session/working-directory/*`、`shutdown` 这几个请求，外加事件流，而且明确写着：

- 没有取消和关闭会话的方法，客户端放弃轮次只能关闭整个运行时进程。
- server→client 请求尚未使用，审批不会推给客户端。

因此：

- **会话彼此隔离**：停止一个会话不会误伤其他会话。
- **空闲会话不占进程**：会话停下后进程退出；用户再次发言时，用 `session/resume` 从加密持久化恢复。
- **并行上限保持 2**，与 3.4.0 相同；同目录或父子目录的会话排队。
- **预热**：用户打开会话页时预先启动 Host，降低首条消息的等待时间。

### 4.2 自建的三个宿主插件

| 插件 | 职责 | 现状 |
|---|---|---|
| `vault-persistence` | 官方 `SessionPersistence` 契约，事件经能力通道写入加密库 | 已有，需改为按事件分行存储（修复审查第 3 项） |
| `clipvault-tools` | 写文件（带差异审批）、接口检查、本机检查、文件核验；新增 `clipboard_search` / `clipboard_read` / `resource_list` / `resource_use` | 现有 6 个工具扩展而来 |
| `clipvault-control` | 注册 `approval/request` 应答者，以及 `ctx.userQuestions` 应答者，经能力通道交给主进程 UI；提供取消当前轮次、查询状态 | 新写 |

注意：官方审批请求**不携带工具参数**，只有工具名和原因。所以写文件、调接口、跑命令这类需要用户看清内容的动作，仍由 `clipvault-tools` 自带的差异审批负责。官方的 bash / pwsh 等工具在 P4 沙箱就绪前不加载。

## 6. 界面设计

### 6.1 信息架构

- **左栏**
  - `新会话`
  - 一级入口：`剪贴板`、`收件箱`（主动建议，带角标）、`资源`
  - 会话列表：按项目分组，状态点区分运行中、等你确认、已完成、已停止
  - 底部：`更多`（项目、TOTP、片段、原有凭证、健康报告）、`设置`
- **中栏：对话**
  - 用户消息、Agent 消息、可折叠的过程行（读了哪些文件、搜了什么）
  - 内联卡片：审批、追问、改动文件、验证结果
  - 输入框：`@剪贴板`、`@资源`、`@文件`、`#项目`、`/技能`
- **右栏：本会话上下文**（可收起）
  - 目标与待办进度
  - 已引用资料（资源以遮罩显示）
  - 改动文件与验证证据
  - 本会话授权：模型、资源、权限级别
- **快速粘贴面板（Alt+Space）**：见第 6.3 节，是找回并粘贴的最快路径。
- 剪贴板和资源的每条记录都有"在会话中使用"。

### 6.2 视觉语言："安静的工作台"

- **去掉像素风**：`Pixelify Sans`、`PixelToast` 这类复古元素退场。
- **基调**：中性灰底 + 白色内容面 + 一个强调色。状态色（运行中、等确认、失败）只用来表达状态。
- **字体**：界面用 `Plus Jakarta Sans` + 系统中文字体；代码、路径、命令用 `IBM Plex Mono`。
- **说话人区分**：用户消息用浅底气泡靠右；Agent 消息不用气泡、全宽排版；过程行字号更小、颜色更浅、默认折叠。
- **密度**：偏紧凑，适合长时间工作；列表用分隔线，不堆卡片。
- **深浅色**：都要支持，全部用 CSS 变量，不写死颜色。

### 6.3 剪贴板：一级功能 + AI 管理

**底线：剪贴板核心不依赖 Harness。** 捕获、存储、搜索、粘贴全部在 Electron 主进程本地完成。模型没配置、Host 起不来、断网时，剪贴板照常可用。

**现有能力保留清单（一项不少）**

| 类别 | 能力 |
|---|---|
| 捕获 | 文本、HTML、图片自动捕获；监听开关；重复复制记为同一条记录的多次发生 |
| 存储 | 加密存储；图片 `.cvimg` 加密；损坏密文保护；保留策略（历史天数、容量、图片天数） |
| 找回 | 关键词/模糊搜索；来源应用、时间筛选；最近复制排序 |
| 管理 | 置顶、长期保存独立副本、删除、多选 |
| 粘贴 | 复制、仅复制图片、仅复制路径、图加路径；`Ctrl+Shift+P` 粘贴最近一条 |
| 安全 | 敏感内容拦截与遮罩、密钥定时自动清除 |
| 片段 | 片段及快捷短语 |
| 唤出 | `Alt+Space` 面板、`Ctrl+Space` 主窗口、`Ctrl+Shift+F` 搜索（均可自定义） |

**找回并粘贴的两条路径**

1. **快速粘贴面板（Alt+Space，最常用）**
   - 不打开主窗口，默认列出最近复制。
   - 输入即筛选，同时搜剪贴板、片段、资源（资源只显示名称）。
   - `Enter` 粘贴回原来的应用；`1-9` 直接粘贴对应条目；`Tab` 以所选内容开新会话（问 AI）。
2. **剪贴板页（主窗口一级入口）**
   - 页内左侧是分组：全部、置顶、长期保存、自动分类（代码、报错、命令、链接、图片、敏感）、按项目。
   - 中间是搜索框和历史列表，前 9 条显示数字快捷键。
   - 右侧是详情，主按钮是"粘贴"，其次是复制、置顶、长期保存、删除、在会话中使用。

**AI 管理分三层**

| 层 | 做什么 | 发给模型的内容 | 默认 |
|---|---|---|---|
| 本地自动整理 | 自动分类；关联项目（按路径、仓库名匹配）；敏感内容遮罩和到期清除；整理建议（"这几条常一起用，存成片段？""有密钥超过 7 天未清除"）；执行保留策略时保护被会话引用的记录 | 无 | 开 |
| AI 找回 | 用一句话描述要找的东西，例如"上周在 payment-api 复制的 nginx 配置"。模型只把这句话翻译成筛选条件（时间、项目、类型、关键词），在本地执行检索，并在界面上展示"AI 理解为…"供核对 | 只有这句话（先脱敏） | 开（未配置模型时退回普通搜索） |
| AI 整理 | 选中若干条后点"让 AI 整理"：起标题、写摘要、合并为片段、拆出资源字段 | 所选条目（脱敏后），发送前确认 | 按需 |

剪贴板历史内容默认不会发给模型；只有用户在会话里引用，或主动点"让 AI 整理"时才会发送。

### 6.4 前端数据流

- 主进程把 Host 的 `session.event` 投影成精简的 UI 事件（消息、过程、审批、追问、目标、待办、改动、状态），经固定 IPC 推给 renderer。
- 原始事件里的文本先统一脱敏，再进入 renderer。
- renderer 只渲染投影结果，不直接接触 Host 或能力令牌。

## 7. 安全模型

- **统一脱敏**：凡是发给模型或渲染给 UI 的文本，都按全部资源秘密脱敏（修复审查第 1 项）。
- **秘密只以引用出现**：会话、导出、日志里只出现资源 ID。
- **审批分级**：只读、逐次确认（默认）、项目内自动。网络访问、写项目外、使用密钥这类高危动作始终逐次确认。
- **沙箱**：P4 引入 Windows ACL 沙箱，把命令的写入限制在项目目录。在此之前保留现有"本机检查不是沙箱"的明确提示。
- **会话存储**：继续加密，改为按事件分行写入。

## 8. 主动智能（收件箱）

| 级别 | 行为 | 是否调用模型 |
|---|---|---|
| L0 本地识别 | 对新复制内容做本地规则分类：报错堆栈、命令、URL、密钥格式、代码块、账号资料 | 否 |
| L1 建议卡 | 在收件箱生成建议："这段报错来自项目 X，要开会话修复吗？""像是一组账号资料，存成资源？""这个密钥和资源 Y 重复" | 否 |
| L2 预分析 | 项目级显式开启后，由后台子 Agent 先读代码给出初判 | 是，默认关闭 |

## 9. 分阶段落地

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0 常驻会话与控制面** | HostManager（按会话起停、并行 2、排队）；`clipvault-control`（审批、追问、取消）；会话分行存储；事件投影；最小对话页（流式消息、审批卡、追问卡、停止、恢复） | 在一个会话里多轮对话、改文件、经审批、停止、重启应用后续接；同时跑两个会话互不影响（均有测试） |
| P1 资料接入 | `@剪贴板` / `@资源` / `@文件`；四个新工具；统一脱敏 | 秘密不出主进程、未选资源的秘密也被隐藏（有测试） |
| P2 新外壳 | 三栏布局、会话列表、右栏上下文、剪贴板页与快速粘贴面板改版（能力不减）、旧模块收进"更多"、新视觉语言 | 1280×820 与 960×640 两种窗口无溢出；键盘可达；第 6.3 节保留清单逐项有回归测试；停掉 Host 后剪贴板照常可用 |
| P3 收件箱与 AI 管理 | 本地自动分类与整理建议；收件箱 L0/L1 建议卡；AI 找回（只发查询）；AI 整理（按需确认）；面板"问 AI" | 复制一段报错后 1 秒内出现建议且没有模型调用；AI 找回的请求里只有查询句（有测试） |
| P4 进阶 | Goal/计划/待办面板完善、子 Agent、Windows ACL 沙箱、定时提醒、会话搜索、旧任务只读迁移、可选 L2 | 沙箱内项目外写入被拒（有测试） |

## 10. 风险与未知

- **rc 版本**：0.2.1-rc.2，SDK 协议明确"无兼容承诺"。需锁版本，并把对官方 API 的调用集中在三个自建插件和 HostManager 里。
- **控制插件依赖内部接口**：审批应答者（`approval/request` waterfall）、`ctx.userQuestions` 应答、轮次取消都要在 P0 先写最小验证，确认能用再展开。
- **进程开销**：每个活跃会话一个 Node 进程，启动需要数秒。靠预热和"空闲即退出"控制。
- **前端工作量**：路线 B 意味着对话渲染、过程折叠、审批/追问卡片都要自己做。P0 只做最小版，P2 再统一视觉。
- **模型供应**：Host 的 provider 为 `deepseek-official`，接 OpenAI 兼容服务要靠现有的协议转换桥，P0 一并回归。
- **工期**：P0 验证通过前不承诺整体工期。
