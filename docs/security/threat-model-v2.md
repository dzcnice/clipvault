# ClipVault v2.0 威胁模型（增量）

> **基线**：`SECURITY.md`（v1.0 威胁模型）
> **适用版本**：v2.0.x
> **配套审计**：`docs/security/audit-report-v2.md`
> **日期**：2026-04-15

本文档仅列出 **v2.0 新特性引入的新威胁面**；v1.0 已覆盖的威胁不再重复。

---

## v2.0 特性地图

| 特性 | 模块 | 新增威胁面 |
|------|------|----------|
| 团队 P2P 协作 | `src/main/p2p/**`, `node-datachannel`, `simple-peer` | 握手 MITM、对端身份伪造、Yjs CRDT 投毒 |
| Vera AI 助手 | `src/main/ai/**`, `openai` | Prompt 注入、上下文泄露、占位符绕过 |
| 加密分享包裹 | `src/main/share/**` | 离线破解分享口令、包裹重放 |
| BIP39 恢复短语 | `src/main/crypto/recovery.ts` | 短语落盘泄露、熵源不足 |
| 凭证审计日志 | `src/db/audit.ts` | 审计记录被清空、日志泄露明文 |
| 健康报告 | `src/renderer/src/pages/HealthReportPage.tsx` | 弱密码统计被泄露给未授权会话 |

## 新增威胁清单

### V2-T1 P2P 握手 MITM

- **攻击者能力**：同局域网 bonjour 广播劫持
- **影响**：建立虚假房间、镜像团队剪贴板
- **缓解**：X25519 临时密钥 + TOFU 指纹 + 用户带外核对
- **残余**：首次配对依赖人工

### V2-T2 Yjs CRDT 投毒

- **攻击者能力**：已加入房间的对端节点
- **影响**：注入恶意文档 / 历史
- **缓解**：每条消息使用团队 DEK AES-256-GCM 加密；未解密失败则拒绝合并
- **残余**：合法成员作恶无法技术上阻止 → 依赖团队内治理

### V2-T3 Vera AI Prompt 注入

- **攻击者能力**：对凭证备注写入「忽略指令 / system override」
- **影响**：诱导 AI 泄露占位符明文 / 绕过审计
- **缓解**：占位符仅在出口替换；AI 上下文仅含 token；审计日志强制落盘
- **残余**：用户**授权使用**时的「请显示占位符 A」不被拦截

### V2-T4 AI 上下文意外包含敏感字段

- **攻击者能力**：无攻击者，属于实现缺陷范畴
- **影响**：明文 value 泄露给第三方 AI 厂商
- **缓解**：`vera-context-builder` 单元测试强制验证输出不含真实 value
- **残余**：用户手动粘贴明文到对话框不在防护范围

### V2-T5 分享包裹离线破解

- **攻击者能力**：获得 `.cvshare` 文件
- **影响**：暴力口令得明文
- **缓解**：scrypt 派生 + 独立导出口令；推荐 ≥ 12 位
- **残余**：弱口令用户自担风险

### V2-T6 分享包裹重放

- **攻击者能力**：截获旧版本 `.cvshare`
- **影响**：用历史权限覆盖当前状态
- **缓解**：包裹内含 `createdAt` + 凭证 UUID + 版本号；导入时由用户确认覆盖
- **残余**：用户误点「覆盖」无法撤销（除非主密码模式下备份）

### V2-T7 BIP39 恢复短语泄露

- **攻击者能力**：读取临时渲染状态（内存 / 截图）
- **影响**：拿到恢复短语 = 拿到 DEK 重建能力
- **缓解**：短语仅在 Recovery 页面按需生成，不落盘；关闭页面即从内存清除；复制到剪贴板时触发 30s 清空
- **残余**：截图 / 抄写泄露由用户负责

### V2-T8 审计日志被清空

- **攻击者能力**：已解锁 vault 的主进程调用
- **影响**：无法追溯恶意访问
- **缓解**：audit_log 表禁止 DELETE IPC（仅支持追加 + 归档）
- **残余**：文件系统层面删除数据库仍可能，属 v1.0 已接受风险

### V2-T9 健康报告信息泄露

- **攻击者能力**：未授权会话调用健康报告 IPC
- **影响**：枚举弱密码凭证列表
- **缓解**：IPC 在 unlocked 状态下才可用；`wrapHandler` 校验
- **残余**：UI 截图泄露

### V2-T10 AI 费用 / 密钥泄露

- **攻击者能力**：读取设置文件
- **影响**：盗用用户 OpenAI API key
- **缓解**：AI key 由 DEK 加密存储；解锁才可解密
- **残余**：同 v1.0 内存 dump

---

## 接受风险（v2.0 明示）

1. 团队协作**假设对端是可信队友**，不防御内部威胁
2. AI 明文出口最终由用户操作决定，Prompt 防护是**深度防御**而非绝对保证
3. 未启用代码签名；用户须从官方 GitHub Release 获取

## 与 v1.0 的接口

| v1.0 威胁 | v2.0 是否改变 |
|----------|--------------|
| 离线暴力破解 | 无变化 |

| IPC 伪造 | `wrapHandler` 继续强制 |
| 导出泄露 | 新增 `.cvshare` 走独立加密路径 |
